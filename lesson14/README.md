#### 22. Контрольные вопросы

1. Чем Ansible отличается от Terraform?
Terraform отвечает за создание, слежку за состоянием и удаление инфраструктуры, Ansible отвечает за настройку конфигурации готовой ВМ (установку пакетов, запуск приложений и т.п.).

2. Зачем нужен inventory?
Inventory содержит список управляемых Ansible узлов и параметров для подключения к ним. Также он позволяет запускать команды сразу на всех узлах из списка.

3. Что делает become: true?
become: true временно повышает привилегии при выполнении задач Ansible, позволяя обычному пользователю совершать действия, разрешенные только root.

4. Что такое идемпотентность?
Идемпотентность означает, что одинаковая последовательность действий дает одинаковый результат (к примеру, если требуемое состояние ВМ было достигнуто при первом запуске плейбука, то второй запуск ничего не изменит).

5. Чем command отличается от специализированного Ansible-модуля?
Модуль command запускает команду напрямую в ОС (без оболочки) и предназначен для любых операций.
Специализированные Ansible-модули предназначены для конкретных операций на уже развернутых ВМ и декларативны.

6. Зачем нужен handler?
handler нужен для того, чтобы определенные задачи выполнялись только в случае получения уведомления от других задач (например, чтобы службы не перезапускались без необходимости). Обычно используется для действий, которые нужно выполнить после изменения конфигурации (например, перезапустить ту или иную службу).

7. Когда выполняется notify?
notify (и handler, на который он указывает) выполняется, если задача, в которой он помещен, имеет статус changed.

8. Зачем проверять nginx -t?
nginx -t проверяет корректность синтаксиса и конфигурации nginx до перезапуска службы. Т.е. это позволяет обнаружить и исправить ошибки до того, как будут применены новые настройки nginx.

9. Что делает proxy_pass?
proxy_pass указывает, на какой ip-адрес (и, как следствие, на работающее на этом адресе приложение) следует перенаправлять поступившие запросы.

10. Почему Docker-приложение можно оставить доступным только на 127.0.0.1:80?
Доступ к Docker извне осуществляется путем перенаправления запросов через Nginx, но при этом к самому приложению нельзя обратиться напрямую из внешней сети, что повышает безопасность.

11. В чём преимущество схемы: Internet → Nginx → Application перед: Internet → Application?
Как уже говорилось выше, наличие nginx повышает безопасность, т.к. к приложению нельзя обратиться напрямую из Интернета. Также централизованную обработку запросов nginx можно настраивать, перенаправлять к различным приложениям или распределять на несколько копий одного и того же приложения.
При использовании схемы Internet → Application обработку пришлось бы настраивать напрямую в самом приложении или в дополнительных компонентах.

12. Что произойдёт, если Docker-приложение остановить?
nginx по-прежнему будет работать и принимать внешние запросы, однако не сможет передавать их приложению (т.к. оно будет недоступно) и будет возвращать клиенту ошибку 502.
