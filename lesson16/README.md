# Занятие 16. Логирование: ищем причины ошибок с Grafana Loki

**Теория — 40 минут, практика — 80 минут.** Продолжаем занятие 15: там Prometheus показывал, что сервис недоступен, а сегодня научимся разбираться, *почему* он не работает.

Работаем на **своей ВМ Ubuntu Server в VirtualBox** (2 CPU, 4 ГБ RAM), как в занятии 15. Облако не нужно. Все команды выполняем на ВМ, браузер открываем на ноутбуке.

```text
Тестовое приложение → Docker JSON-логи → Grafana Alloy → Loki → Grafana Explore
```

**Важно:** логи могут содержать пароли, токены и персональные данные. Никогда не записывайте секреты в логи и не публикуйте настоящие рабочие логи в учебных репозиториях.

## Теория (40 минут)

1. **Лог — это запись о событии.** Например: «12:30, запрос /checkout, ответ 500». Логи помогают восстановить последовательность действий перед ошибкой.
2. **Метрики и логи отвечают на разные вопросы.** Метрика показывает, сколько ошибок произошло; лог помогает понять, что произошло в конкретном запросе. Трейсы показывают путь запроса через сервисы.
3. **Уровни логов:** DEBUG — подробности для отладки, INFO — обычная работа, WARN — подозрительная ситуация, ERROR — ошибка. Уровень сам по себе не говорит, что сервис недоступен.
4. **Структурированные логи:** JSON с полями `timestamp`, `level`, `service`, `request_id`, `message` удобнее искать, чем произвольный текст.
5. **Централизация:** когда контейнеров много, неудобно заходить на каждый сервер. Alloy собирает записи, Loki хранит и ищет их, Grafana показывает.
6. **Метки Loki:** `service`, `environment` помогают выбрать поток. Не делайте метками уникальные `request_id`, URL с параметрами или user_id — это создаёт слишком много потоков.
7. **Хранение:** логи занимают диск; в нашем учебном Loki хранение ограничено семью днями. Для production нужны доступы, резервирование, политики хранения и защищённая передача.

## Подготовка (10 минут до занятия)

На Windows откройте VirtualBox → ВМ → **Настроить → Сеть → NAT → Проброс портов**. Добавьте TCP: порт хоста **3000** → гостя **3000** (Grafana). Порт 3100 наружу не пробрасываем: Loki доступен только внутри Docker-сети.

```bash
ssh -p 2222 <ваш_пользователь>@localhost
cd ~/devops-lab && git pull
cd lesson16/practice
docker compose version
free -h
df -h /
```

Желательно иметь 2 ГБ доступной памяти и 5 ГБ свободного диска. **Не запускайте одновременно стек занятия 15**: у него тоже Grafana на порту 3000. Если он остался запущен, остановите его в папке `lesson15/practice`.

### Часть 1. Логи без отдельной системы (10 минут)

```bash
sudo journalctl -u docker --since "15 minutes ago" --no-pager | tail -20
docker ps
```

`journalctl` читает журнал systemd, а `docker logs` — вывод конкретного контейнера. Если Docker запущен не как systemd-сервис, первая команда может ничего не показать — это нормально.

**Вопрос:** что неудобно в `docker logs`, если у вас 30 серверов?

### Часть 2. Поднимаем стек (15 минут)

```bash
cd ~/devops-lab/lesson16/practice
cp .env.example .env
nano .env                    # замените учебный пароль
docker compose config --quiet && echo "Конфигурация корректна"
docker compose up -d
docker compose ps
docker compose logs --tail=30 alloy
curl -fsS http://localhost:8080/health
```

Образы могут скачиваться несколько минут. Если Docker Hub недоступен, используйте реестр/зеркало из главного README курса или попросите преподавателя заранее подготовить образы. Не копируйте пароли в чат.

В браузере Windows откройте **http://localhost:3000**. Войдите: `admin`, пароль из `.env`. Источник Loki уже добавлен автоматически через provisioning.

В **Connections → Data sources → Loki** нажмите **Save & test**. Затем **Explore**, выберите Loki.

> На Mac с Docker Desktop команды те же, но SSH и VirtualBox не нужны.

### Часть 3. Ищем ошибку (20 минут)

Создайте несколько событий:

```bash
curl -s http://localhost:8080/
curl -s http://localhost:8080/health
curl -s -i http://localhost:8080/fail
curl -s -i http://localhost:8080/slow
docker compose logs --tail=15 app
```

В Grafana → **Explore** выберите Loki, временной диапазон **Last 15 minutes**. Переключитесь на режим **Code** и выполните:

```logql
{service="demo-app"}
```

Вы должны увидеть JSON-записи приложения. Если записей пока нет, подождите 10–20 секунд, обновите диапазон времени и проверьте `docker compose logs alloy`.

Найдите ошибку:

```logql
{service="demo-app"} | json | level="ERROR"
```

Раскройте строку и найдите `request_id`, `path`, `status` и `message`. Сравните с результатом `curl /fail`.

### Часть 4. Учимся LogQL (15 минут)

**Все логи приложения:**
```logql
{service="demo-app"}
```

**Только ошибки:**
```logql
{service="demo-app"} | json | level="ERROR"
```

**Только медленные запросы:**
```logql
{service="demo-app"} | json | duration_ms >= 500
```

**Сколько ошибок было за последние 5 минут:**
```logql
sum(count_over_time({service="demo-app"} | json | level="ERROR" [5m]))
```

Последний запрос удобнее смотреть как **Time series**. Если ошибок нет, результат может быть пустым — сначала вызовите `/fail` несколько раз.

**Вопросы:** чем `| json` отличается от фильтра по метке? Почему `request_id` полезен внутри записи, но не в метках Loki?

### Часть 5. Мини-расследование (15 минут)

Запустите:

```bash
for i in 1 2 3; do curl -s -o /dev/null http://localhost:8080/; done
curl -s -o /dev/null http://localhost:8080/slow
curl -s -o /dev/null http://localhost:8080/fail
```

Представьте, что пользователи жалуются на ошибки. В Grafana найдите запись с `status=500`. Запишите время, `request_id`, путь, текст ошибки и предложите первое действие инженера. Затем найдите медленный запрос и объясните, почему медленный ответ не обязательно означает HTTP 500.

**Подсказка:** эталонные запросы есть в `../solution/queries.md`. Сначала попробуйте самостоятельно.

### Часть 6. Уборка (5 минут)

```bash
docker compose down -v
docker compose ps -a
```

`-v` удаляет учебные тома с логами и настройками Grafana. Образы остаются. Если нужно сохранить результаты для домашней работы, сначала выполните ДЗ или скопируйте запросы в свой файл.

## Типичные проблемы

| Проблема | Что проверить |
|---|---|
| Grafana не открывается | Проброс 3000 в VirtualBox, `docker compose ps`, порт не занят уроком 15 |
| Loki datasource недоступен | `docker compose logs loki`; адрес внутри сети — `http://loki:3100`, не localhost |
| Нет логов | `docker compose logs alloy`, затем `docker compose logs app`; временной диапазон Explore |
| Ошибка парсинга LogQL | Проверьте фигурные скобки, кавычки и наличие `| json` |
| `permission denied` при чтении Docker-логов | Проверьте доступ Alloy к Docker socket и `docker compose logs alloy` |
| Контейнер перезапускается | `docker compose logs <имя>`, `free -h`, `df -h` |
| `localhost:8080` не отвечает | `docker compose ps app`; проверьте, что порт 8080 свободен |

**Безопасность:** доступ к Docker socket даёт широкие полномочия на Docker-хосте. В учебной ВМ это допустимое упрощение, но для production нужен отдельный дизайн безопасности и ограничение доступа.
