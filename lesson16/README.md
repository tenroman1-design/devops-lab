# Занятие 16. Централизованное логирование с Grafana Loki

**40 минут теории и 80 минут практики.** На занятии 15 мы использовали Prometheus и Grafana, чтобы заметить проблему. Теперь разберём отдельный запрос: найдём запись о нём, проверим HTTP-статус и сформулируем, что произошло и что стоит проверить дальше.

На практике используем отдельное учебное HTTP-приложение. Оно специально возвращает ошибку на `/fail` и отвечает с задержкой на `/slow`.

## Что нужно знать перед практикой

- **Метрики** показывают изменение показателей во времени. Например, можно увидеть рост доли HTTP 5xx, если приложение публикует соответствующий счётчик. Метрика `up` с занятия 15 показывает, удалось ли Prometheus собрать метрики с цели.
- **Логи** описывают отдельные события. На практике в каждой записи о запросе будут время, уровень, путь, HTTP-статус, длительность, `request_id` и сообщение.
- **Трейсы** связывают этапы обработки запроса. Идентификатор в нашей записи помогает найти событие этого приложения. Распределённую трассировку в стенде не настраиваем.
- Уровни `DEBUG`, `INFO`, `WARN` и `ERROR` отражают важность события по правилам приложения. Уровень и HTTP-статус хранятся в разных полях.
- Alloy читает вывод приложения через Docker API и отправляет записи в Loki. Loki индексирует метки потоков, например `service` и `environment`. Уникальные идентификаторы запросов оставляем полями JSON, чтобы число потоков не росло с каждым запросом. Grafana Explore отправляет запросы LogQL в Loki и показывает результаты.

## Подготовка до занятия

Используйте ту же ВМ Ubuntu Server в VirtualBox, что и на занятии 15. Облако для практики не требуется. Для ВМ достаточно учебной конфигурации с 2 vCPU и 4 ГБ RAM. Проверьте свободное место командой `df -h /`. На Mac с Docker Desktop команды можно выполнять в терминале Mac.

1. Подключитесь из Windows Terminal или PowerShell командой `ssh -p 2222 <ваш_пользователь>@localhost`. Проверьте `docker compose version` и `docker ps`.
2. Для Grafana используйте правило VirtualBox TCP **3000 → 3000** с занятия 15. Для приложения проброс порта не нужен: `curl` запускается в терминале ВМ.
3. Убедитесь, что Grafana с занятия 15 работает. Если стек остановлен, запустите его привычным способом из `lesson15/practice` командой `docker compose up -d --pull never`. Войдите в Grafana и убедитесь, что источник Prometheus доступен. Стек оставляем запущенным на всё занятие.
4. Заранее обновите репозиторий и скачайте образы по той же схеме, что на занятии 15.

```bash
cd ~/devops-lab
git pull
cd lesson16/practice
bash pull-logging-images.sh
```

Скрипт проверяет, есть ли нужный образ локально. Затем пробует публичное зеркало курса в GHCR и, если оно недоступно, Docker Hub. Скачиваем только Loki, Alloy и Python для учебного приложения. Grafana уже работает в стеке занятия 15. Дождитесь сообщения «Готово: все образы на месте». При ошибке сохраните сообщение Docker: оно поможет различить проблему DNS, доступа к реестру и скачивания конкретного образа.

## Практика

Команды выполняйте в `lesson16/practice` в терминале ВМ или Mac. Grafana открывайте в браузере по адресу `http://localhost:3000`.

### 1. Где искать логи без Loki · 10 минут

```bash
sudo journalctl -u docker --since "15 minutes ago" --no-pager | tail -20
docker ps
```

`journalctl` показывает журнал службы Docker на Ubuntu с systemd. На Mac пропустите эту команду. Позже сравним этот журнал с выводом приложения через `docker compose logs app`. Обсудите, как вы стали бы искать один запрос, если бы приложение работало на 30 серверах.

### 2. Запустите стенд и подключите Loki · 15 минут

Создайте локальный файл настроек, если его ещё нет.

```bash
test -f .env || cp .env.example .env
docker network ls --filter label=com.docker.compose.network=default
```

При стандартном запуске сеть занятия 15 называется `practice_default`. Если её нет в списке, узнайте имя сети по работающему контейнеру Grafana:

```bash
cd ../../lesson15/practice
docker inspect "$(docker compose ps -q grafana)" --format '{{range $name, $_ := .NetworkSettings.Networks}}{{println $name}}{{end}}'
cd ../../lesson16/practice
```

Если при запуске занятия 15 вы указывали `-p`, добавьте тот же аргумент к `docker compose ps -q grafana`. Запишите полученное имя в `MONITORING_NETWORK` в файле `.env` занятия 16, затем выполните команды запуска. Если порт 8080 занят, задайте `APP_PORT=18080` и используйте этот порт во всех командах `curl` к приложению.

```bash
docker compose config --quiet
docker compose up -d --pull never
docker compose ps
curl -fsS http://localhost:8080/health
```

В `docker compose ps` занятия 16 должны появиться три сервиса: `loki`, `alloy` и `app`. Если первая проверка `/health` не удалась сразу после запуска, повторите её через несколько секунд.

Войдите в Grafana с тем же паролем, что на занятии 15. Откройте **Connections → Data sources → Add data source → Loki**. Укажите имя **Loki** и URL **`http://lesson16-loki:3100`**. Оставьте Prometheus источником по умолчанию. Нажмите **Save & test**. Если Loki уже добавлен, проверьте URL в его настройках. При первой попытке Loki может ещё запускаться. Подождите и повторите проверку.

Адрес `lesson16-loki` виден Grafana через общую Docker-сеть. Порт Loki публиковать на ВМ не нужно. Откройте **Explore**, выберите **Loki**, режим **Code** и период **Last 15 minutes**. Для контрольной проверки переключитесь на Prometheus, выполните `up` и вернитесь к Loki.

### 3. Найдите конкретную ошибку · 20 минут

```bash
curl -sS http://localhost:8080/
curl -sS -i http://localhost:8080/fail
curl -sS -i http://localhost:8080/slow
docker compose logs --tail=15 app
```

Запишите `request_id` из JSON в ответе на `/fail`. Выполните в Explore запрос `{service="demo-app"}`, затем найдите нужную запись по идентификатору.

```logql
{service="demo-app"} | json | request_id="ВАШ_REQUEST_ID"
```

Подставьте полученное значение вместо `ВАШ_REQUEST_ID`. Разверните строку. Сверьте `request_id`, путь и статус с HTTP-ответом. Скажите своими словами, что сообщило приложение. Учитывайте, что сбой базы данных здесь имитируется.

### 4. Составьте запросы LogQL · 15 минут

```logql
{service="demo-app"} | json app_level="level" | app_level="ERROR"
```

```logql
{service="demo-app"} | json | duration_ms >= 500
```

```logql
sum(count_over_time({service="demo-app"} | json app_level="level" | app_level="ERROR" | __error__="" [5m]))
```

Селектор в фигурных скобках выбирает потоки по меткам. `| json` извлекает поля из записей. `json app_level="level"` извлекает уровень приложения под отдельным именем, чтобы он не смешивался с уровнем, который Loki может определить автоматически. Последний запрос считает записи уровня ERROR за пятиминутное окно. Фильтр `__error__=""` исключает ошибки разбора перед подсчётом. В режиме **Instant** результат относится к концу выбранного диапазона. Для текущего подсчёта поставьте конец диапазона на **Now**. При отсутствии совпадений Grafana может показать `No data`.

### 5. Проведите мини-расследование · 15 минут

Один студент вызывает `/`, `/slow` и `/fail`, затем сообщает напарнику примерное время сбоя. Второй находит в Loki запись с HTTP 500, выписывает время и часовой пояс, путь, статус, сообщение и `request_id`. Первый сверяет идентификатор с HTTP-ответом. Затем найдите медленный запрос и сравните его статус со статусом ошибки.

Сформулируйте первое действие дежурного в аналогичной рабочей ситуации. Например, проверить ошибки и задержки обращений к базе в тот же интервал и сопоставить их с запросом. После самостоятельной попытки можно свериться с [примерами запросов](solution/queries.md).

### 6. Остановите стенд · 5 минут

```bash
docker compose down
docker compose ps -a
```

Обычная остановка сохраняет именованные тома. Если учебные логи больше не нужны, используйте `docker compose down -v`. Эта команда удалит том Loki. Источник Loki сохранится в Grafana и снова заработает при следующем запуске стенда. В Explore можно сразу вернуться к Prometheus. Сохраните текст отчёта до удаления.

## Если возникла проблема

| Симптом | Что проверить |
|---|---|
| Grafana не открывается | `docker compose ps` в папке занятия 15, проброс порта 3000, запущен ли стек занятия 15 |
| `curl` к приложению завершается ошибкой | `docker compose ps app`, `docker compose logs app`, значение `APP_PORT` |
| Grafana не подключается к Loki | `docker compose logs --tail=50 loki`. Проверьте URL `http://lesson16-loki:3100` и `MONITORING_NETWORK` |
| В Explore нет записей | Проверьте текущее время и диапазон, вызовите `/fail` заново, затем выполните `docker compose logs --tail=30 app alloy` |
| Счётчик пуст | Проверьте конец временного диапазона и наличие свежего ERROR в пятиминутном окне |
| Alloy сообщает об ошибке доступа | Проверьте вывод `docker compose logs alloy` и доступность Docker socket в среде запуска |

Хранение в Loki настроено на семь суток. Контейнер учебного приложения отдельно ротирует локальные Docker-логи. Доступ Alloy к Docker socket даёт широкие полномочия на Docker-хосте даже при монтировании с `:ro`. Запускайте стенд в учебной среде. Не записывайте в логи пароли, токены и персональные данные.
